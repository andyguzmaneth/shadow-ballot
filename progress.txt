## Codebase Patterns
- @noble/secp256k1 v3 API: `Point` (not `ProjectivePoint`), `etc.mod()`, `etc.invert()`, `hashes.sha256` (not `etc.sha256Sync`)
- @noble/hashes v2 exports require `.js` suffix: `@noble/hashes/sha3.js`, `@noble/hashes/utils.js`
- noble/secp256k1 v3 `verify()` always hashes msg with sha256 internally — cannot use it for keccak256-hashed messages. Use manual ECDSA verify instead.
- Curve order N hardcoded: `0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141n`
- Must initialize noble hashes before use: `hashes.sha256 = ...` and `hashes.hmacSha256 = ...`
- noble/secp256k1 v3: `utils.randomSecretKey()` (not `randomPrivateKey`)
- noble/secp256k1 v3: Point uses `.toBytes(compressed)` (not `.toRawBytes()`)
- noble/secp256k1 v3: `getPublicKey(privKey, true)` for compressed, `false` for uncompressed
- ethers.js v6 Transaction: use `Transaction.from({...})` to build, `.unsignedHash` for digest, inject `Signature.from({r, s, yParity})` into `.signature`, then `.serialized` for signed hex
- ethers.js v6 Signature.from: `yParity` must be typed as `0 | 1`, cast with `as 0 | 1`
- RPC fallback pattern: iterate SEPOLIA_RPC_URLS array, try each, throw after all fail
- Hardhat 2 required for this project (Hardhat 3 incompatible with @nomicfoundation/hardhat-toolbox). Use `hardhat.config.cjs` for ESM projects (`"type": "module"` in package.json).
- ethers.js v6 human-readable ABI: use string array format like `'function foo(uint256 x) returns (uint256)'` — simpler than JSON ABI for config.
- Contract helpers: use `JsonRpcProvider` + `Wallet` from ethers for read/write contract instances.
- UI: vanilla TS, no framework. Tab panels are `#panel-voter`, `#panel-coordinator`, `#panel-explorer`. Toggle `.active` class.
- CSS variables for theme: `--bg-primary`, `--bg-card`, `--accent` (#00e5a0), `--text-primary`, `--font-mono`. Use `.mono` class for addresses/hashes.
- `renderApp()` in main.ts is the entry point. View modules in `src/views/` export `init*View()` functions called after DOM render.
- Coordinator keys generated once, stored in localStorage (`shadow-ballot-coordinator`). Shared across views.
- Vote announcements (txHash, ephemeralPubKey, etc.) stored in localStorage (`shadow-ballot-announcements`) for coordinator scanning.
- Vote records stored in localStorage (`shadow-ballot-votes-cast`) to track voted proposals.
- Demo proposals hardcoded in `config.ts` `DEMO_PROPOSALS` array (contract not deployed yet).

  - Transaction.from(signedHex) can parse back and recover the sender address via ecrecover — good for validation
  - yParity in Signature.from must be `0 | 1` type, not `number` — needs cast

- Vote encoding: 2 bytes (proposalId + choice). Candidate set = 3N for N proposals.
- castVoteOffline() is the testable version (no RPC); castVote() is the live version with broadcast.
- decodeVote uses unsignedTxHash (not txHash) as the "public message" for nonce derivation — must match what was signed.
