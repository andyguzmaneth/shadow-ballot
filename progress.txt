## Codebase Patterns
- @noble/secp256k1 v3 API: `Point` (not `ProjectivePoint`), `etc.mod()`, `etc.invert()`, `hashes.sha256` (not `etc.sha256Sync`)
- @noble/hashes v2 exports require `.js` suffix: `@noble/hashes/sha3.js`, `@noble/hashes/utils.js`
- noble/secp256k1 v3 `verify()` always hashes msg with sha256 internally — cannot use it for keccak256-hashed messages. Use manual ECDSA verify instead.
- Curve order N hardcoded: `0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141n`
- Must initialize noble hashes before use: `hashes.sha256 = ...` and `hashes.hmacSha256 = ...`
- noble/secp256k1 v3: `utils.randomSecretKey()` (not `randomPrivateKey`)
- noble/secp256k1 v3: Point uses `.toBytes(compressed)` (not `.toRawBytes()`)
- noble/secp256k1 v3: `getPublicKey(privKey, true)` for compressed, `false` for uncompressed
- ethers.js v6 Transaction: use `Transaction.from({...})` to build, `.unsignedHash` for digest, inject `Signature.from({r, s, yParity})` into `.signature`, then `.serialized` for signed hex
- ethers.js v6 Signature.from: `yParity` must be typed as `0 | 1`, cast with `as 0 | 1`
- RPC fallback pattern: iterate SEPOLIA_RPC_URLS array, try each, throw after all fail
